# 実装ルール

[ai_context.md](ai_context.md) の範囲を超える機能、画面、ルート、テーブル、パッケージを足しません。`tasks.md` の未完了の先頭 1 件以外は実装しません。

## 入力

フォーム、アップロード、URL から来た値は、使う前に検証します。無効なら保存も削除もせず、理由を日本語で出します。

- ユーザー名は空にしない。使える文字は英数字とアンダースコアだけです。50 文字を超えたら拒否します。
- 保存前にユーザー名を小文字へそろえ、`username_normalized` へ入れます。重複はこの列で判定します。画面と `username` には、入力された大文字小文字を残します。
- ログイン時も、入力を小文字へそろえて `username_normalized` で探します。
- メールアドレスは空にしない。254 文字までです。形式の確認は email-validator を使い、配信先の DNS 確認はしません。小文字へそろえた値を `email_normalized` へ入れ、重複はこの列で判定します。
- パスワードは 8 文字未満を拒否します。エラーで画面に戻すとき、パスワード欄は空にします。
- キャプションは空文字を許します。NULL にはしません。200 文字を超えたら拒否します。修正しても `created_at` は変えません。
- 写真は 1 枚必須です。拡張子は png、jpg、jpeg、gif だけを受けます。拡張子だけで判断せず、Pillow で開いて PNG、JPEG、GIF のどれかかを確認します。5MB を超えたら拒否します。保存名は UUID に、Pillow で判定した形式の拡張子を付けたものにし、利用者のファイル名でパスを作りません。`uploads/posts/` の外は読み書きしません。

登録、ログイン、投稿、修正、削除の POST は、CSRF トークンが一致するときだけ処理します。一致しなければ処理せず、理由を出します。

ユニーク制約に当たったときも、成功扱いしません。登録画面に理由を出します。

## 失敗

データベースやファイル操作の結果は受け取ります。失敗を成功として次へ進めません。

- 投稿の行を削除できなければ、写真ファイルは残します。
- 行の削除に成功したあと、ファイル削除に失敗したら、その失敗をログに残し、成功として一覧へ移しません。
- 一覧の取得に失敗したら、空の成功画面にしません。

## データベース

- モデルは `User` と `Post` だけです。`BlobField`、いいね、コメントのモデルは作りません。
- `Post.user` は `ForeignKeyField(User, backref="posts", on_delete="RESTRICT")` にします。列名は `user_id` です。
- SQLite へ接続するときに `PRAGMA foreign_keys = ON` を実行します。
- `DateTimeField` の初期値には、現在時刻を返す関数を渡します。`datetime.now()` をその場で呼びません。
- パスワードは Werkzeug のハッシュを `password_hash` に保存し、照合もハッシュ用の関数で行います。
- インデックス候補の `created_at` と `user_id` は、必須の作業が終わるまで作りません。
- 開発中に列を足したら、`create_tables` は既存テーブルを変更しません。ローカルの SQLite ファイルを消して作り直します。

## 秘密情報と生成ファイル

- `SECRET_KEY` などの秘密情報は `.env` から読み、コードと Git に置きません。
- `.env`、SQLite ファイル、`flask_session/`、`instance/`、`uploads/posts/` の写真は Git に含めません。`.gitignore` では `uploads/posts/*` を除外し、空のフォルダーを残すための `uploads/posts/.gitkeep` だけを追跡します。
- セッションの保存先は Flask-Session のファイルシステムです。ログイン状態の中身をブラウザのクッキーへは置きません。

## 画面

- HTML は `templates/`、CSS は `static/css/`、JavaScript は `static/js/` に置きます。投稿画像は `static/` に置きません。
- 未ログインの人に投稿作成、修正フォーム、削除ボタンを出しません。
- 投稿者以外には、修正フォームと削除ボタンを出しません。修正と削除の前にも、ログイン中のユーザーが投稿者かを確認します。
- 存在しない投稿は詳細の中身を出さず、見つからない旨と一覧へ戻るリンクを出します。
