# 写真共有アプリ 要件定義

Flask と Peewee で作る、インスタグラムのタイムラインに似た写真共有アプリの要件です。写真を中心に、短いキャプションといいねがある一覧を目指します。検索、フォロー、ユーザー別ページ、写真の差し替え、クラウドへの保存、デプロイは範囲外です。実行環境は PC の中だけです。

## アプリの概要

友人同士が、旅行や日常の写真を 1 か所のタイムラインで見せ合う Web アプリです。

- 投稿は写真 1 枚と、空でもよい短いキャプションです。
- 一覧はログインしていなくても見られます。投稿、いいね、修正、削除にはログインが必要です。
- みんなの写真が、新しい順に 1 つのタイムラインに並びます。
- 実行環境は自分の PC の中だけです。デプロイやインターネットへの公開はしません。データベースは SQLite、写真ファイルはアプリと同じ PC の `uploads/` に保存します。
- 画面は Flask のテンプレートで返し、ページを移動しながら使います。

## 想定ユーザー

写真を見せ合う友人です。見るだけの人と、投稿する人がいます。

- 見る人は、アカウントがなくてもタイムラインを開けます。いいねの件数は見られますが、いいねはできません。
- 投稿する人は、ユーザー名とパスワードで登録し、ログインしてから写真を投稿します。自分の投稿だけ、キャプションの修正と削除ができます。

## 必須機能

上から順に実装できる大きさに分けています。番号の小さいものから作ってください。

### 1. ユーザー登録

- ユーザー名とパスワードだけを入力して登録できる。
- ユーザー名は他の人と重複できない。
- パスワードはハッシュにして保存し、平文では保存しない。
- ユーザー名が空、既に使われている、パスワードが空、といった無効な入力は登録しない。理由を画面に出す。

### 2. ログイン

- 登録済みのユーザー名とパスワードでログインできる。
- ユーザー名またはパスワードが違うときはログインさせず、理由を画面に出す。
- ログイン中であることを、次の画面でも覚えておく。

### 3. ログアウト

- ログイン中のユーザーがログアウトできる。
- ログアウト後は、未ログインの状態に戻る。

### 4. 写真を 1 枚投稿する

- ログイン中だけ投稿できる。未ログインならログイン画面へ戻す。
- 写真 1 枚は必須。キャプションは空でもよい。キャプションは 200 文字まで。
- 受け付ける画像は JPEG と PNG。1 枚の上限は 5MB。
- 写真ファイルは `uploads/` に保存する。データベースには、保存したファイル名だけを書く。
- 保存するファイル名はこちらで付け、投稿者が付けたファイル名はパスに使わない。
- 写真がない、形式が違う、大きすぎる、キャプションが長すぎる場合は保存しない。理由を画面に出す。

### 5. 投稿一覧を見る

- ログインしていなくても、みんなの投稿を 1 つのタイムラインで見られる。
- 並び順は新しい投稿が先。
- 各投稿には、ユーザー名、写真、キャプション、いいね数、投稿日時を表示する。
- 写真は `uploads/` から Flask が返す。

### 6. 自分のキャプションを修正する

- ログイン中の投稿者だけが、自分の投稿のキャプションを修正できる。
- 写真の差し替えはできない。
- 他人の投稿は修正できない。
- 空のキャプションも許す。200 文字を超える場合は保存せず、理由を画面に出す。

### 7. 自分の投稿を削除する

- ログイン中の投稿者だけが、自分の投稿を削除できる。
- 他人の投稿は削除できない。
- 削除するときは、データベースの投稿と、その投稿へのいいねを消し、続けて `uploads/` の写真ファイルを消す。
- ファイル削除に失敗した場合は、失敗を記録し、成功として扱わない。

### 8. いいねを付ける・取り消す

- ログイン中のユーザーだけが、1 つの投稿に 1 回いいねできる。
- 同じ投稿でもう一度操作すると、いいねを取り消す。
- 未ログインの人は件数だけ見て、いいねはできない。いいねしようとしたらログイン画面へ戻す。
- 一覧に、その投稿のいいね数を表示する。

## 余裕があれば追加する機能

必須機能が動いてからにしてください。今回足すならコメントだけです。

### コメント

- ログイン中のユーザーが、投稿に短いコメントを残せる。
- 一覧または投稿の近くで、その投稿のコメントを読める。

検索、フォロー、ユーザー別の写真ページは、コメントの次にも作りません。

## 非機能要件

- 技術は Flask と Peewee。パスワードのハッシュは Flask に含まれる Werkzeug を使う。これ以外のライブラリは足さない。
- データは SQLite の 3 テーブルに分ける。
  - ユーザー: ユーザー名、パスワードのハッシュ、作成日時
  - 投稿: 投稿者、保存ファイル名、キャプション、作成日時
  - いいね: どのユーザーがどの投稿に付けたか、作成日時。同じユーザーと投稿の組は 1 件だけ
- 実行環境は開発に使う PC の中だけにする。同じ PC のブラウザから、その PC で起動したアプリを開く。
- デプロイ、公開用サーバー、コンテナ化はしない。そのための設定ファイルも置かない。
- 写真はローカルの `uploads/` だけに置く。アップロード先の設定をクラウド向けに分岐させない。
- 登録、ログイン、投稿、修正、削除、いいねのフォームは、セッション上のトークンで正当な画面からの送信か確認する。
- フォーム、アップロード、URL から来た値は、使う前に検証する。無効なら処理しない。
- データベースやファイル操作が失敗したら、失敗のまま呼び出し側へ返す。失敗を成功として先へ進まない。

## 実装時に注意すべきこと

- 必須機能の 1 から 8 の順で作り、1 つ動いてから次へ進む。コメントは最後で、動かなくても必須機能の完了とみなす。
- 未ログインで投稿、いいね、修正、削除に来た場合は、その処理をせずログイン画面へ戻す。
- 修正と削除の前に、ログイン中のユーザーがその投稿の投稿者か確認する。
- 写真の保存名は UUID など、予測しにくくパスにならない名前にする。利用者が送ったファイル名で `uploads/` の外を読み書きしない。
- いいねは、データベース側でも「1 ユーザーにつき 1 投稿 1 件」になるよう制約する。
- 投稿削除は、データベースの行を消してから写真ファイルを消す。ファイル削除に失敗したらログに残し、成功メッセージだけ出して終わらない。
- `uploads/` と SQLite のファイルは Git に含めない。
- 範囲を広げない。ユーザー別ページ、検索、フォロー、写真の差し替え、クラウド保存、デプロイは実装しない。
