矛盾したときは、機能の範囲は `requirements.md`、画面に出すものは `screen-design.md`、URL と失敗時の移動は `routing-design.md`、列と制約は `database.md` を優先します。作業の進め方は [tasks.md](tasks.md)、実装中の判断は [coding_rules.md](coding_rules.md) に従います。

## いまの状態

`tasks.md` の 1 から 7 は実装済みです。ただし、一覧から投稿詳細へ進むリンクは、投稿詳細（作業 8）と一緒に付けます。このファイルを読んだ段階では、コードをまとめて実装せず、`tasks.md` の未完了の先頭 1 件だけを行います。

## 作るもの

友人同士が、旅行や日常の写真を 1 か所のタイムラインで見せ合う Web アプリです。実行環境は開発に使う PC の中だけです。同じ PC のブラウザから開きます。デプロイ、公開用サーバー、コンテナ化はしません。

画面の言葉は日本語です。ボタン、エラー文、入力欄のラベルも日本語です。

## 画面

画面は 5 つです。

| 画面 | パス | ログイン |
|---|---|---|
| 投稿一覧 | `GET /` | 不要 |
| 投稿詳細 | `GET /posts/<id>` | 閲覧は不要。修正と削除は必要 |
| ユーザー登録 | `GET /register`、`POST /register` | 不要 |
| ログイン | `GET /login`、`POST /login` | 不要 |
| 投稿作成 | `GET /posts/new`、`POST /posts` | 必要 |

一覧と詳細には、ユーザー名、写真、キャプション、投稿日時を出します。メールアドレスは出しません。キャプションの修正と削除は投稿詳細に置き、別画面は作りません。

ヘッダーは次のとおりです。

- 未ログイン: 「ログイン」「ユーザー登録」。投稿一覧へ戻れる。
- ログイン中: 「投稿作成」「ログアウト」。投稿一覧へ戻れる。ログイン中のユーザー名も出す。

## ログイン

ログインはユーザー名とパスワードです。メールアドレスではログインしません。

- 登録に成功したら `/login` へ移る。すでにログイン中なら `/` へ移る。
- ログインに成功したら、いつも `/` へ移る。投稿作成の途中でログイン画面に来た場合も同じです。
- ログアウトしたら、未ログインの `/` へ移る。
- 未ログインで投稿作成、修正、削除に来たら、処理せず `/login` へ移る。

ログイン状態の中身は、Flask-Session でサーバー側の `flask_session/` に置きます。ブラウザには識別子だけを渡します。

## データ

テーブルは `user` と `post` だけです。モデル名は `User` と `Post` です。

- `user`: ユーザー名、小文字にしたユーザー名、メールアドレス、小文字にしたメールアドレス、パスワードのハッシュ、登録日時
- `post`: 投稿者（`user_id`）、保存ファイル名、キャプション、投稿日時

写真の中身はデータベースに入れません。ファイルはプロジェクト直下の `uploads/posts/` に置き、データベースには UUID などの保存ファイル名だけを書きます。利用者のファイル名はパスに使いません。

1 人のユーザーは複数の投稿を持てます。投稿は `user_id` で 1 人の投稿者を指します。

## 入力

- ユーザー名は必須。英数字とアンダースコアだけ。50 文字まで。`alice` と `Alice` は同じ名前です。画面には入力された文字のまま出します。
- メールアドレスは必須。形式がメールアドレスであること。254 文字まで。大文字と小文字が違うだけでも同じアドレスです。ログインと画面表示には使いません。
- パスワードは 8 文字以上。ハッシュだけを保存します。
- キャプションは空文字でもよい。200 文字まで。写真の差し替えはしません。
- 写真は PNG、JPEG、GIF のどれか。1 枚。5MB まで。必須です。

## ファイルの分け方

- `app.py`: 起動、設定、ルート
- `models.py`: `User` と `Post`
- `forms.py`: Flask-WTF のフォーム
- `templates/`: HTML
- `static/css/`: CSS
- `static/js/`: JavaScript
- `uploads/posts/`: 投稿画像。`static/` には置かない。`/uploads/posts/<filename>` で Flask が返す

秘密情報は `.env` から読み、コードに書きません。

## 使ってよいパッケージ

`requirements.txt` にあるものだけを使います。中心は Flask と Peewee です。パスワードのハッシュと、保存済み画像をブラウザへ返す処理は、Flask に含まれる Werkzeug を使います。画像の形式確認は Pillow、メールアドレスの形式確認は email-validator、フォームと CSRF は Flask-WTF、ログインユーザーの取得は Flask-Login、セッションの保存先は Flask-Session、環境変数は python-dotenv です。これ以外のパッケージは足しません。

## 作らないもの

いいね、コメント、検索、フォロー、ユーザー別ページ、写真の差し替え、画像のデータベース保存、クラウド保存、デプロイ、自動テスト、公開用サーバーの設定は実装しません。コメントは必須機能の完了に含めません。
